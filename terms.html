本节定义了本规范及整个decentralized identifier基础设施中使用的术语。本规范中每次出现这些术语时都会包含指向其定义的链接。

authenticate
认证（authenticate）是一个过程，通过该过程，实体可以使用一个或多个verification methods来证明其拥有特定属性或控制特定秘密。对于DIDs，一个常见的例子是证明对与DID document中发布的公钥相关联的加密私钥的控制。
binding
绑定（binding）是client调用DID resolver的具体机制。这可以是local binding（如本地命令行工具或库 API），也可以是remote binding（如 HTTP(S) 绑定）。参见节。
client
客户端（client）是调用DID resolver以执行DID resolution和/或DID URL dereferencing算法的软件和/或硬件。此调用通过binding完成。client一词不暗示任何特定的网络拓扑。
decentralized identifier (DID)
去中心化标识符（DID）是一种全局唯一的持久性标识符，不需要集中式注册机构，通常以加密方式生成和/或注册。DID 的通用格式在中定义。特定的DID scheme在DID method规范中定义。许多（但非全部）DID 方法利用distributed ledger technology（DLT）或其他形式的去中心化网络。
DID controller
DID 控制器是有能力对DID document进行更改的实体。一个DID可能有多个 DID 控制器。DID 控制器可以通过DID document顶层的可选 `controller` 属性来表示。注意，DID 控制器可能就是DID subject。
DID delegate
DID 委托是指DID controller通过DID document授权其使用与DID关联的verification method的实体。例如，控制子女DID document的父母可能允许子女使用其个人设备进行authenticate。在这种情况下，子女就是DID delegate。子女的个人设备将包含使其能够使用该DID进行authenticate的私有加密材料。但是，未经父母许可，子女可能不被允许添加其他个人设备。
DID document
DID 文档是描述DID subject的一组数据，包括DID subject或DID delegate可用于authenticate自身并证明其与该DID关联的机制（如加密公钥）。
DID fragment
DID 片段是DID URL中第一个井号字符（#）之后的部分。DID 片段语法与 URI 片段语法相同。
DID method
DID 方法是对特定DID method scheme如何实现的定义。DID 方法由 DID 方法规范定义，该规范指定了创建、解析、更新和停用DIDs和DID documents的精确操作。参见。
DID path
DID 路径是DID URL中以第一个正斜杠（/）字符开始（含该字符），以问号（?）字符、片段井号（#）字符或DID URL结尾为止的部分。DID 路径语法与 URI 路径语法相同。参见。
DID query
DID 查询是DID URL中第一个问号字符（?）及其之后的部分。DID 查询语法与 URI 查询语法相同。参见。
DID resolution
DID 解析是以DID和一组解析选项作为输入，返回符合规范的representation的DID document及附加元数据的过程。此过程依赖于适用DID method的"Read"操作。此过程的输入和输出在中定义。
DID resolver
DID 解析器是执行DID resolution功能的软件和/或硬件组件，以DID作为输入，产生符合规范的DID document作为输出。
DID resolution result
DID 解析结果是表示DID resolution算法结果的数据结构。可能包含DID document。参见节。
DID scheme
DID 方案是decentralized identifier的形式化语法。通用 DID 方案以前缀 did: 开头，如中所定义。每个DID method规范定义一个与该特定DID method配合使用的特定 DID 方法方案。在特定的 DID 方法方案中，DID 方法名称位于第一个冒号之后，以第二个冒号结束，例如 did:example:
DID subject
DID 主体是由DID标识并由DID document描述的实体。任何事物都可以是 DID 主体：人、群组、组织、物理事物、数字事物、逻辑事物等。
DID URL
DID URL 是DID加上符合中定义的任何附加语法组件。这包括可选的DID path（带有前导 / 字符）、可选的DID query（带有前导 ? 字符）和可选的DID fragment（带有前导 # 字符）。
DID URL dereferencing
DID URL 解引用是以DID URL和一组输入元数据作为输入，返回一个resource的过程。该资源可能是DID document加附加元数据、DID document中包含的次级资源，或完全位于DID document外部的资源。该过程使用DID resolution来获取由DID URL中包含的DID所指示的DID document。然后解引用过程可以对DID document执行附加处理，以返回由DID URL指示的被解引用资源。此过程的输入和输出在中定义。
DID URL dereferencer
DID URL 解引用器是对给定的DID URL或DID document执行DID URL dereferencing功能的软件和/或硬件系统。
DID URL dereferencing result
DID URL 解引用结果是表示DID URL dereferencing算法结果的数据结构。可能包含DID document或其他内容。参见节。
distributed ledger (DLT)
分布式账本是一种用于记录事件的非集中式系统。这些系统为参与者建立了足够的信心，使其能够依赖他人记录的数据做出运营决策。它们通常使用分布式数据库，其中不同节点使用共识协议来确认加密签名交易的排序。随时间推移对数字签名交易的链接通常使账本的历史记录实际上不可篡改。
resource
如 [[RFC3986]] 所定义："……术语'资源'以一般意义使用，指代可由 URI 标识的任何事物。"类似地，任何资源都可以作为由DID标识的DID subject。
representation
如 [[RFC9110]] 为 HTTP 所定义的表示形式："旨在以可通过协议轻松通信的格式反映给定资源的过去、当前或期望状态的信息。表示形式由一组表示元数据和一个可能无限的表示数据流组成。"DID document是描述DID subject信息的表示形式。参见。
local binding
本地绑定是指client调用运行在同一网络主机上的DID resolver的binding，例如通过本地命令行工具或库 API。在这种情况下，DID resolver有时也被称为"本地DID resolver"。参见节。
remote binding
远程绑定是指client调用运行在不同网络主机上的DID resolver的binding，例如通过 HTTP(S) 绑定。在这种情况下，DID resolver有时也被称为"远程DID resolver"。参见节。
services
服务是通过一个或多个service endpoints与DID subject或相关实体进行通信或交互的方式。示例包括发现服务、代理服务、社交网络服务、文件存储服务和可验证凭证存储库服务。
service endpoint
服务端点是一个网络地址（如 HTTP URL），services在该地址代表DID subject运行。
unverifiable read
不可验证读取是DID resolver与verifiable data registry之间对DID method's"Read"操作的低置信度实现，用于获取DID document。对结果的完整性和正确性没有保证。参见节。
verifiable data registry
可验证数据注册表是一个促进decentralized identifiers和DID documents的创建、验证、更新和/或停用的系统。可验证数据注册表也可能用于其他加密可验证的数据结构，如verifiable credentials。更多信息请参见 W3C 可验证凭证规范 [[VC-DATA-MODEL]]。
verification method

验证方法是一组参数，可与某个过程一起使用以独立验证证明。例如，加密公钥可用作针对数字签名的验证方法；在此用法中，它验证签名者拥有相关联的加密私钥。

此定义中的"验证"和"证明"旨在广泛适用。例如，加密公钥可能在 Diffie-Hellman 密钥交换期间用于协商用于加密的共享对称密钥。这保证了密钥协商过程的完整性。因此它是另一种类型的验证方法，即使对该过程的描述可能不使用"验证"或"证明"这些词语。

verifiable read
可验证读取是DID resolver与verifiable data registry之间对DID method's"Read"操作的高置信度实现，用于获取DID document。在适用DID method可能的范围内，对结果的完整性和正确性有保证。参见节。
Universally Unique Identifier (UUID)
通用唯一标识符（UUID）是由 [[RFC4122]] 定义的一种全局唯一标识符。UUID 与 DID 类似，不需要集中式注册机构。UUID 与 DID 的不同之处在于它们不可解析且不可加密验证。
Uniform Resource Identifier (URI)
统一资源标识符（URI）是 [[RFC3986]] 定义的万维网上所有资源的标准标识符格式。DID是一种 URI 方案类型。
